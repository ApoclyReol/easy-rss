# RSS Reader 设计系统

本文档定义当前 Streamlit 界面的信息层级、文案、状态颜色和交互约束。目标是让“未读推荐”与原有阅读篮子保持同一套心智模型。

## 1. 设计原则

1. 先显示论文，再显示模型判断；推荐是辅助信息，不遮挡标题、摘要和原文链接。
2. 主动作必须是主动触发；抓取新论文不等于自动筛选。
3. 任何改变论文状态的批量操作都要有明确范围、数量和确认。
4. 隐藏可恢复，推荐结果可追溯；不使用删除来表达“不相关”。
5. 同一个状态在列表浏览和快速处理中的文案、颜色和流转保持一致。

## 2. 页面信息架构

```text
应用标题与自动更新提示
  ├─ 文献阅读
  │   ├─ 状态篮子
  │   ├─ 订阅源 / 搜索 / 显示数量
  │   ├─ 未读推荐面板
  │   └─ 列表浏览 / 快速处理
  ├─ 订阅管理
  └─ 兴趣分析
```

独立“筛选工具”不再作为导航入口。推荐功能只在未读篮子出现，避免用户在页面之间切换。

## 3. 推荐层级与颜色语义

| 层级 | 中文文案 | 视觉语义 | 允许动作 |
| --- | --- | --- | --- |
| `high` | 高相关 | 蓝色主色、优先位置 | 感兴趣、打开原文、隐藏 |
| `pending` | 待判断 | 中性色/琥珀提示 | LLM 复核、人工处理 |
| 未评分 | 未评分 | 灰色辅助文字 | 更新推荐 |
| `low` | 低相关 | 低强调度灰色或浅红提示 | 确认后批量隐藏、恢复 |

状态篮子本身仍使用原有语义：`未读 / 感兴趣 / 已归档 / 已隐藏 / 已过期`。推荐层级不能替换状态篮子。

## 4. 控件规范

### 主按钮

- “更新关键词推荐”：主按钮，每次从当前人工状态完整重建模型。
- “LLM 复核待判断”：次按钮，只处理待判断项。
- 按钮旁应显示当前模型时间或待处理数量，避免用户误以为系统正在后台运行。

### 批量隐藏

- 必须在可展开区域内展示范围与数量。
- 使用确认复选框后才启用按钮。
- 操作完成后显示撤回入口和实际改变数量。

### 卡片

- 标题是第一视觉层级，保持原文链接能力。
- 期刊为辅助元信息。
- 推荐信息使用一行短标签：`高相关 · 84 · 关键词 · social simulation`。
- 不在卡片中显示长篇 LLM 理由；详细模型信息放在推荐设置或诊断信息中。

## 5. 文案规范

- 使用“待判断”，不要使用“模型不确定”作为用户标签。
- 使用“隐藏”，不要使用“删除”。
- 使用“更新关键词推荐”，不要使用“训练模型”，避免夸大系统行为。
- 使用“LLM 复核待判断”，不要使用“自动筛选全部论文”。
- 错误信息说明下一步动作，例如“训练样本不足，请先处理更多论文”，不要只显示异常堆栈。

## 6. 响应式与可访问性

- 推荐统计使用四列指标，但在窄窗口仍应按 Streamlit 默认布局折行。
- 按钮文案必须独立表达动作，不依赖颜色才能理解。
- 标题链接、按钮和确认区域保持足够的可点击区域。
- 不用颜色作为唯一状态标识，始终同时显示中文层级文字。

## 7. 组件边界

- `app/views/reader.py`：篮子、卡片、快速处理和阅读页布局。
- `app/views/recommendation.py`：推荐面板、词表设置、LLM 设置和批量隐藏入口。
- `app/services/recommendation_service.py`：文本处理、训练、评分和分层。
- `app/repositories/recommendation_repository.py`：推荐数据的 SQLite 读写。

新增 UI 行为应优先复用这些边界，不要把 SQL 或模型训练逻辑放进 Streamlit 页面函数。
