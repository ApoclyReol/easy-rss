# RSS Reader 个性化推荐 PRD

状态：`v1.1.0` 实现版

## 1. 背景与问题

RSS Reader 的主要价值是帮助用户从持续到来的论文中快速找到值得阅读的内容。旧流程需要在独立筛选页维护规则，筛选结果与文献阅读篮子分离，容易打断阅读节奏。

用户已经通过“感兴趣、归档、隐藏、过期”等状态积累了个人偏好数据。产品应利用这些真实选择，先用可解释的关键词模型对未读论文排序，再把边界论文交给 LLM 复核。

## 2. 产品目标

- 将推荐直接放入未读篮子，形成“抓取 → 推荐 → 阅读 → 反馈”的闭环。
- 用历史人工状态学习关键词偏好，减少每天挑选论文题目的时间。
- 推荐只改变排序和标签，不自动改变论文状态。
- 对低相关论文提供当前筛选范围内的确认式批量隐藏，并支持撤回。
- 保留关键词、分数、模型版本和 LLM 结果，让推荐可解释、可复盘。

## 3. 非目标

- 不替代 Zotero、文献管理器或正式的研究资料库。
- 第一版不训练或微调大语言模型，不引入向量数据库。
- 不在应用启动、RSS 自动更新或页面打开时自动调用 LLM。
- 不根据推荐结果直接删除论文；隐藏和过期仍是可恢复状态。

## 4. 目标用户与核心流程

用户是持续阅读社会科学、信息资源管理、人工智能及相关交叉领域论文的个人研究者。

```text
打开应用
  ↓
自动获取 RSS 新论文
  ↓
进入“文献阅读 / 未读”
  ↓
点击“更新关键词推荐”
  ↓
高相关 → 待判断 → 未评分 → 低相关
  ↓                 ↓
人工阅读反馈       点击“LLM 复核待判断”
  ↓                 ↓
感兴趣/归档/隐藏 ← 高相关或低相关
```

## 5. 功能需求

### 5.1 未读篮子推荐

- 未读列表按“高相关、待判断、未评分、低相关”排序，同层按最新抓取时间排序。
- 卡片显示相关层级、关键词分、结果来源和最多三个命中关键词。
- 推荐摘要显示当前模型更新时间、训练样本数和各层数量。
- 新论文在下一次主动更新推荐前保持“未评分”。

### 5.2 关键词模型

- 正样本：`interested`、`archived`。
- 负样本：`hidden`、`expired`；两者都来自用户此前的手动隐藏。
- `unread` 不参与训练，只接受评分。
- 标题重复输入以提高权重，摘要作为补充；作者和期刊不作为模型特征。
- 英文和中文文本统一分词，使用 TF-IDF 一元/二元词组和类别平衡逻辑回归。
- 无关键词证据时以 50 分作为中性点，避免负样本数量过多造成默认低分。

默认阈值：

| 分数 | 层级 | 行为 |
| ---: | --- | --- |
| 70–100 | 高相关 | 优先阅读 |
| 31–69 | 待判断 | 可交给 LLM 复核 |
| 0–30 | 低相关 | 靠后展示，可确认后隐藏 |

训练样本不足、文本为空或模型训练失败时，论文保持未评分并展示错误信息。

### 5.3 词表管理

- 展示自动关键词、正负方向、权重、正负样本数。
- 支持新增人工正向/负向关键词。
- 支持禁用错误关键词、设置人工权重、恢复自动权重。
- 人工修正只在下一次“更新关键词推荐”时进入模型计算。

### 5.4 LLM 复核

- 只处理当前仍为待判断、且没有成功复核结果的未读论文。
- 请求包含标题、摘要、兴趣描述、关键词分和正负关键词证据。
- LLM 必须严格返回 `high` 或 `low`。
- 成功结果覆盖最终层级，但保留原关键词分和模型版本。
- 单篇失败保留在待判断层，下一次只重试失败项。

### 5.5 批量隐藏与撤回

- “一键隐藏低相关”只作用于当前订阅源和搜索条件覆盖的全部低相关未读论文，不受显示数量限制。
- 执行前需要用户勾选确认。
- 批量操作写入现有 `hidden` 状态，不删除论文。
- 最近一次批量隐藏可通过“撤回”恢复为未读。

## 6. 数据与接口约束

推荐数据存储在 SQLite：

- `recommendation_scores`：单篇论文分数、层级、LLM 结果、命中词和模型版本。
- `recommendation_keywords`：自动权重、样本统计和人工修正。
- `recommendation_models`：每次主动重建的版本、样本数量和错误信息。

主论文状态仍只使用 `items.item_status`，推荐层级不替代论文状态。

## 7. 验收标准

- 新安装后运行 `./run.sh` 可以创建环境、安装依赖并启动 Streamlit。
- 启动和 RSS 更新不改变推荐分数，不发起 LLM 请求。
- 完整测试集通过，中文/英文文本和正负样本不平衡测试通过。
- 数据库和 API 配置不会进入 Git。
- 用户可以只通过未读篮子完成推荐、复核、阅读、隐藏和撤回。
- 推荐模型失败时不会把论文误标为低相关。

## 8. 后续迭代

- 增加“暂时不看”反馈，避免把犹豫误当成负样本。
- 增加 recommendation run 的历史对比和误判回顾。
- 正样本积累后评估 embedding 作为补充证据，而不是替代可解释关键词模型。
